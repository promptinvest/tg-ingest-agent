## Result and architecture

The old validator accepted arbitrary conclusions with real citation IDs and could
omit requested hosts. Existing accepted receipts remain evidence of their narrower
checks. This release extends the existing fleet skill with `fleet_context` and
`fleet_report`, retaining the closed router, pinned restricted executor/gateways,
networkless research worker and exact one-time maintenance cards.

Canonical owner-bound context carries hosts/projects/facets/focus and original/
latest questions. Named project changes override inherited fleet scope; unrelated
owner turns and edited/stale sources end the frame. Old receipts remain readable.
Observations distinguish observed, unavailable, not found, not configured and
dated records, with source/timestamp/window. Unknown states are not inactive counts.
The model selects finding IDs, bounded hypothesis types and optional read facets.
All factual selections are checked before code bounds their count. Unsupported optional exploration is refused and recorded independently, preserving valid findings. Factual wording
and every requested host's coverage belong to code. Complete reports split into
bounded pages, with per-page durable receipts and no automatic ambiguous replay.
One extra read retains original scope and per-facet times, inside original budgets.

All six gateways collect LoadState. Only PI's observation-policy unit names change:
the nonexistent old names become the actual health-watch/encrypted-backup timers.
No health/backup service is started, stopped or reconfigured. Missing protocol,
backup-result, CI/issue/repository instrumentation remains an explicit capability
gap. Two snapshots do not establish stability; active units do not prove end-to-end
application or client-route health. Hypotheses are limited to supported types,
not unrestricted model diagnosis or new shell execution.
